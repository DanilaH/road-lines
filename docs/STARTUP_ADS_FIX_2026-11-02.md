# Исправление зависания загрузки после монетизации

2 ноября 2026. Пользователь сообщил: последний APK остаётся с сообщением «Запуск занимает слишком много времени. Перезапусти приложение».

## Подтверждённая ошибка

В main стояло `await monetization.init()` перед установкой core lifecycle и `platformReady`. В свою очередь init последовательно ждал native listener, восстановление receipt и `status()`. Зависший ответ статуса необязательной рекламной системы не давал снять startup cover.

В отдельной ads-test сборке ДО исправления эмулирован никогда не отвечающий status: спустя16 секунд `data-ready` отсутствует, на startup cover именно сообщение пользователя. Это воспроизводит конкретный дефект цепочки запуска. Логи с телефона не получены; причина, по которой native RPC не ответил именно на устройстве пользователя, отдельно не установлена.

Второй обнаруженный риск: receipt blocker мог остановить Phaser loop до первого postrender. Меню после снятия blocker не обязано будить игровой loop; ожидание первой отрисовки тогда не завершалось бы. До первого render теперь loop не усыпляется; после него блокировки по-прежнему останавливают renderer.

## Исправление

- Ядро lifecycle/Back/visibility и первый видимый кадр не ждут рекламную инициализацию.
- Init стартует в фоне; listener регистрируется отдельно, поздний handle удаляется после dispose.
- `status()` не является частью обязательной загрузки. RPC status/pending/ack и создание bridge имеют конечный deadline5с; зависший status оставляет рекламу недоступной и допускает ограниченные повторы.
- Проверка native earned receipts сохраняет блокировку ценных действий, пока её исход неизвестен. Зависший pending показывает понятный отдельный retry, не бесконечный startup cover; pending не удаляется и монеты не угадываются. Ack остаётся только после durable grant, exact ID/sequence ledger не меняются.
- Первый render разрешён даже при стартовой блокировке. Это не разрешает gameplay/audio за рекламой или в фоне: после первого кадра обычные blockers действуют.
- GameSave v5, заработанное, цены и ориентация не менялись. Очистка данных/переустановка с удалением прогресса для этого исправления не требуются.

## Проверки

`node tools/startup-ads-smoke.mjs --reproduce-before` — на исходном runtime воспроизведён15с warning при зависшем status.

`node tools/startup-ads-smoke.mjs` — три изолированных сценария:

1. Status никогда не отвечает: startup cover снимается, можно войти в игру и открыть/закрыть паузу.
2. Pending receipts отвечают с задержкой650мс: видимый запуск не зависает, после проверки игра доступна.
3. Pending никогда не отвечает: появляется интерфейс, затем отдельное уведомление/повтор; нет бесконечного loading и нет неподтверждённых мутаций.

Дополнительно запускаются427 app/kit tests, monetization UI и persistence. CI добавлен отдельный startup-ads job. Обычная production-сборка не включает эти фикстуры. Android APK компилируется с прежним официальным SDK и demo placements; повторный запуск именно на физическом устройстве остаётся проверкой пользователя.
