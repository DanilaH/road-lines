# Этап 3 — подарки, предложение темы, ежедневное колесо

Дата: 2026-10-30.

## Поведение
Колесо: отдельный тёмный экран из главного меню, 8 равных секторов 20/30/50/75/100/150/200/300, фиксированный указатель, 3.6 с замедления, звук и частицы после выдачи. Один бесплатный запуск за локальную дату, countdown до полуночи. Максимальная использованная дата не откатывается; перевод часов назад не возвращает попытку.
Результат выбирается crypto Uint32 % 8 (8 делит диапазон без смещения). До вращения сохраняются id/date/sector и расход попытки. Начисление только из сохранённого результата. После reload незавершённый результат начисляется один раз до запуска UI. Back/фон/resize отменяют presentation и завершают ту же операцию; dispose оставляет durable pending для следующего запуска.
Предложение темы: после 10 первых прохождений, затем минимум через 20 новых; только ещё закрытая тема, фиксированные target level и milestone. На Continue отдельное окно; отказ возвращает в тот же результат. Переключение уровня/повтор не переносит старое предложение на новую победу. Уже открытые темы не предлагаются.
Видеокнопки темы и дополнительного вращения явно недоступны. Никаких поддельных ad-earned выдач; реальный rewarded и receipt journal — этап 4.
Подарки: общая шкала по банку, +100 на 20/40/60/80 первых прохождениях. Grant сохраняется атомарно с first-clear/base reward и ledger milestone; popup только подтверждает уже полученное. Повтор не продвигает шкалу. Gift acknowledgement не владеет валютой.
Уточнение прежнего неоднозначного пункта плана: используется общий прогресс, а не сброс внутри каждого 30-уровневого набора. Это согласует отметки 20/40/60/80 и уже существующий общий счётчик.

## Persistence и kit
JSON v3 на прежнем key; миграция v1/v2 сохраняет кошелёк, themes, completed и drafts. Новые ценные ledgers проверяются строго; invalid v3 не сбрасывается.
WheelService применяет vendored DurablePendingTransactionSession. stage/commit адаптеры пишут через единственный GameStore из текущего store.state, а не из устаревшего снимка session. Перед входом prefix flush; load действительно читает durable state. Pending identity включает id/date/sector. Lost ack проверяет writer, session выполняет authoritative reload; неподтверждённые исходы блокируют слепой повтор.
Двойной prepare защищён busy; commit идемпотентен по spinId, чужой id отвергается. Main использует generation/session checks, отменяет WAAPI/timers/частицы, снимает clock/listeners и запрещает записи сервиса после dispose.

## Проверки
До технической очистки workspace прошли 145 tests (97 kit + 48 application), inspect/production browser flows и Android sync. После очистки локальная папка восстановлена из pinned GitHub base и сохранённых скриптов/текста; свежий CI на восстановленном commit обязателен и записывается ниже.
Unit: gift thresholds 0–90 и idempotence, offer cadence/target/replay, v2 migration, stage→reload→commit, concurrent prepare, rollback даты, stale id, failed stage/commit, lost ack, purchase/path/reward между stage и commit, corrupt ledger, dispose.
Browser: прежние 15 input-прохождений/пять viewport/menus/themes; дополнительно wheel layout на 320×568/360×800/390×844/412×915/576×1280, двойной spin, сохранённый outcome до анимации, точный сектор под указателем, reload во время spin, Back/фон без поздней повторной награды, перевод даты назад/вперёд, disk-full, реальный tenth-clear offer и отказ без потери base reward.

## Границы
Банк пока 15, поэтому первый подарок на 20-й задаче недостижим в обычной игре. Пороговая политика проверена unit-тестом до 90; фактический threshold grant/popup через 20 реальных уровней нужно проверить при расширении банка на этапе 5. Нельзя называть текущий банк 90-уровневым или считать этот сценарий device-accepted.
Нет нативной рекламы/дополнительной rewarded попытки/earned unlock. Нет physical-device acceptance звука, вибрации, Back, font-scale/insets. APK debug; подписанный store release — отдельный этап.
