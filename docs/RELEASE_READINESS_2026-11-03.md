# Перед выпуском Road Lines

Дата:3 ноября2026. Пользователь предложил закончить кнопочный звук и переходить к продакшену. Новые механики/контент/редизайн в этот этап не входят.

## Подтверждено

- 90 уровней, портретная ориентация, настройки/сохранения/монетизация реализованы; автоматические проверки и отдельные evidence —в репозитории.
- Исправлены зависимость доступа к игре от receipt recovery, музыкальный диссонанс и кнопочный feedback. Установка нового playtest APK поверх прежнего сохраняет его данные при прежнем signer/package.
- Текущий Android workflow запускает assembleDebug, ROAD_LINES_PLAYTEST=true, ROAD_LINES_AD_MODE=demo. Это тестовый .playtest пакет; наличие secrets live IDs не превращает его в live-сборку.

## Что закрыть до production

| Шаг | Текущее основание / следующий результат |
|---|---|
| Production signing/build | В проверенном workflow только debug и cached debug keystore. Нужна постоянная release-подпись и отдельный проверяемый release-процесс; не выдавать debug APK за store-релиз. |
| Live ad configuration | Генератор умеет live и три YANDEX_*_AD_UNIT_ID, но текущий APK содержит demo-* blocks. Наличие/корректность secrets через доступные инструменты не подтверждены. Нужны свои Android banner/interstitial/rewarded IDs, live-config и проверка без сети/no-fill на телефоне. |
| Production analytics | Workflow использует APPMETRICA_DEBUG_API_KEY. Нужны production app/key и подтверждённая доставка событий отдельно от тестового проекта. |
| Store materials/privacy | В исходниках не найдены отдельный готовый комплект карточки и URL опубликованной privacy policy. Подготовить название/описание/иконку/скриншоты и декларации по фактическим SDK/конфигурации; публикация в кабинете не выполнялась. |
| Final device check | Короткий прогон именно release candidate: запуск/офлайн/жесты/reset/hint/пауза/звук/фон, покупка, награда и real banner/fullscreen, затем restart. Нет утверждения, что это уже пройдено на физическом телефоне. |

Основной production ID —com.danilah.roadlines, playtest —com.danilah.roadlines.playtest. Это отдельные Android sandbox и данные: не обещать автоматический перенос тестового прогресса в другой package. Не менять подпись уже опубликованного production-приложения, если оно существует; его состояние в кабинете этой проверкой не установлено.

Порядок: зафиксировать release-идентичность/ключ и live-конфигурацию → собрать/проверить один candidate → заполнить карточку по фактическому бинарнику → передать на публикацию. Пользовательские ключи не запрашивать текстом в чате; использовать настроенное защищённое build environment. Ничего в магазине не опубликовано этим проходом.
