# Road Lines — решения проекта

## 2026-10-29: Android-first вместо Yandex Games web bootstrap
Контракт продукта: TypeScript + Phaser + Vite + Capacitor; Android/RuStore, портрет. Нативная реклама Yandex Mobile Ads.
Шаблон kit bootstrap/yandex-phaser предназначен для Yandex Games web, использует веб-SDK, GameplayAPI/LoadingAPI и landscape/portrait gate. Его обязательная политика относится к новым Yandex Games web-проектам, которым Road Lines сейчас не является.

Замена: отобранные framework-independent модули с точными source SHA плюс собственный Capacitor scaffold на этапе 0. Сохраняем принципы: real/mock separation, осмысленный first-presentable-frame, диагностика запуска, безопасный viewport, cleanup и отдельная release-приёмка.
Не переносим веб-Player Data, веб-рекламу, Yandex DRAFT/upload audit и landscape sizing как рабочие Android-механизмы.
Если появится отдельный Yandex Games web target, пересмотреть bootstrap для этого target явно.
Доказательство текущего этапа: API/исходники/тесты донора проверены; Android scaffold ещё не создан.

## 2026-10-29: playable stage 1
Чистая модель маршрута и bounded DFS solver отделены от Phaser. Ввод на DOM host считает пересечения отрезка с центральными прямоугольниками клеток в CSS px; это сохраняет промежуточные клетки даже при одном быстром pointermove. Только ортогональные последовательные рёбра, только последовательный обратный откат. Pointer capture, cancel, exit, resize, пауза и фон завершают жест без сброса маршрута.
Worker создаётся на запрос и terminate на отмену/изменение prefix. Solver budget 200 мс, внешний deadline 1500 мс учитывает запуск worker. FOUND/UNSOLVABLE/UNKNOWN различаются; списание только после durable save найденной полезной подсказки. Бледное продолжение — до трёх следующих клеток. Доказанный тупик может предложить ближайший проверенный откат.
Первый банк: 15 собственных масок, 3–25 клеток. Полные witnesses проверяет отдельный Node validator, который не импортирует игровой solver/model. Канонизация по 8 симметриям исключает повтор одинаковой формы. Witness не ограничивает принимаемое решение.
Сохранение v1 — один компактный JSON localStorage с синхронной атомарной заменой. Обычный prefix coalesced таймером 80 мс, flush на завершении жеста/паузе/фоне/pagehide. Победа, coins и first-clear сохраняются вместе сразу. Маленький state пока не требует JsonStorageRepository/RevisionSnapshotQueue; не добавлять вторую очередь записей без реальной нужды. Внутренняя baseline обновляется только после подтверждения записи; ambiguous write проверяется обратным чтением. Неизвестный исход блокирует дальнейшие mutations до reload.
Браузер удерживает Web Lock на save всю сессию; вторая вкладка получает понятный отказ. Дополнительно проверяется raw baseline перед каждой записью и storage events. На старом WebView без Web Locks действует single-instance договорённость + детектор конфликтов, не распределённая CAS-гарантия.
Частично повреждённый prefix/устаревшая версия уровня сбрасывается к start, но coins/completed не угадываются. Нечитаемый durable state сохраняется и показывает ошибку, не silently default.
Базовая награда +20 и first-clear введены сейчас для корректного завершения/повторов. Presentation наград пока статический; звук/haptics, monetization и каталог остаются в следующих этапах.

## 2026-10-30: праздничный цикл / этап 2
BoardScene рисует раскрытие клеток, локальную реакцию головы и трансформацию большой фигуры в миниатюру за 650 мс. На время перехода canvas получает полный viewport, затем возвращается в область результата, чтобы большая фигура не обрезалась контейнером миниатюры.
WinMotion владеет только presentation: DOM WAAPI title/stars/reward, fullscreen 2D confetti, 16 visual coin tokens и aggregate counter. Состояние GameStore не передаётся ему для mutations. Используются kit ValueTransferPlan и pitch helpers. Примерный сбор занимает 550 мс; Continue доступно после 650 мс, не после окончания конфетти.
Confetti: 3 очереди 115/100/115 частиц, потолок 360 одновременно, четыре формы включая длинные ленты, capped DPR 2. HUD/title/buttons выше FX. Reduce-motion снижает число частиц/длительности; native haptics имеют отдельную настройку.
Внутренний показанный баланс отделён от durable coins. Победа уже сохранена до старта эффектов. Cancel/background/dispose/viewport resize завершают presentation до истинного баланса, убирают timers/RAF/WAAPI/coins и отменяют ожидающий collect. goNext проверяет revision/blocked/disposed, поэтому отменённый collect не навигирует позже.
Audio — собственные WebAudio plucks/chord/chimes, один context, 20 voices max, rate gates 45 мс cell и 42 мс coin, мягкий master compressor. Cue план/высота/огибающие тестируются; звучание не копирует непрослушанную запись конкурента. На фоне запланированные sources останавливаются и context suspend, на новом жесте — resume, без догоняющих старых нот.
Нативный RoadFeedback plugin регистрируется до BridgeActivity.onCreate. VIBRATE permission, VibratorManager на API31+, amplitude-aware waveform на API26+, timings fallback на API24/25. Win — три сильных раздельных импульса; отдельные cell/star/coin/progress. OnPause/Destroy отменяет вибрацию, устаревший issuedAt >350 мс игнорируется. Browser vibrate — ограниченный fallback, не Android-механизм.
Settings sound/vibration хранятся в независимом noncritical prefs key. Нет новой валюты, профилей, музыки или рекламных SDK. Доступность аппаратного мотора и реальные ощущения подтверждаются только устройством.


## 2026-10-30: этап 3, навигация и маршруты задач
Главное меню открывается при старте; продолжение возвращает текущую игру/результат. Домашний экран — собственная композиция, не утверждение точной копии неизвестного меню конкурента. Наборы и сетка — DOM над прежним Phaser renderer. Один renderer спит вне игры; поля меню не получают скрытый игровой ввод.
Доступность последовательная внутри набора; повтор разрешён всегда для пройденных. В текущем банке первый набор содержит реальные 15, остальные отмечены «Скоро» и не открываются. Полные 3×30 и доступность остальных после трёх обучающих остаются контрактом этапа 5; фиктивные 90 кнопок сейчас не рисуем.
Выбор задач сохраняет отдельные transient drafts с version/path в прежнем JSON v1 (аддитивная миграция). Legacy current prefix переносится без изменения кошелька/прохождений. Текущий path авторитетен над draft. Переключение сначала сохраняет, затем меняет игровой контекст; ошибка не активирует выбранную задачу. Повтор пройденной начинается со старта без повторной первой награды.
На последней задаче Continue ведёт в сетку с завершением набора, не оборачивается на первую молча. Back из результата — главное меню; из игры — пауза; из сетки — наборы; из наборов — главное меню; из настроек/паузы — назад; на главном меню остаётся в приложении.
Настройки sound/vibration переиспользованы в домашнем меню. Каталог, wheel, gift grant и skin offer не входят в этот подэтап и не считаются готовыми.


## 2026-10-30: темы, ownership и схема v2
Каталог содержит 8 собственных палитр, 2 бесплатные/6 по 500. Единый Theme описывает фон/cells/ribbon/trail и UI tokens; Phaser и DOM используют его напрямую. Купленные темы не привязаны к текущему уровню. Никаких новых ассетов/зависимостей или выдачи тестовой валюты в production.
Покупка явно подтверждается; баланс, ownedThemes и themeId сохраняются одним GameStore.write. Применение только после durable truth, повтор бесплатен. Prefix перед входом flush; устаревший полный autosave не держится отдельным producer. Сохранена защита от stale writer и lost ack.
Для ценных прав владения повышена схема до v2 (прежний key). v1 мигрирует без сброса прогресса; отсутствие ownership в v2 не считается legacy. Неверные ownership/selected поля дают recoverable startup error с сохранённым raw, а не потерю покупок/reset.
Возврат из каталога хранит screen + pause state; результат возвращается без replay эффектов/выдачи. Back сначала закрывает подтверждение. Dialog делает catalog inert, фокус удерживается на доступных кнопках; после закрытия возвращается на карточку. Темы не включают будущий skin offer/ads grant автоматически.


## 2026-10-30: оставшиеся экраны этапа 3 и reward ledgers
Колесо использует pinned DurablePendingTransactionSession; stage до анимации, deterministic commit из pending, recovery до UI. Один GameStore, rebase на текущий state, никаких старых полных снимков в адаптере. Id/date/sector фиксируют grant, lastDate монотонна. UI cancels не владеют наградой. Сервис запрещает mutations после dispose.
Схема v3 хранит daily ledger, gift milestones/notice и offer target/cadence. v1/v2 мигрируют без сброса кошелька/тем/маршрутов. Подарок +100 сохраняется вместе с первой победой; окно — acknowledgement.
Уточнение gift scope: общий прогресс банка на 20/40/60/80, без сброса на границе набора. Прежняя формулировка «внутри набора» конфликтовала с глобальными отметками и уже введённой шкалой; план исправлен явно. В текущих 15 задачах actual gift threshold недостижим; не генерируем лишние уровни ради теста UI.
Offer появляется на Continue после 10 первых прохождений, затем не раньше +20. Отказ возвращает результат; переход на другой уровень отменяет старое offer. Получение темы/extra spin за видео не симулируется: до этапа 4 кнопки недоступны.

## 2026-10-30: первые три дополнительные механики
Пользователь разрешил реализацию после подробного исследования. В первый набор добавлены 15 задач: финиш, стенки и упорядоченные точки; см. MECHANICS.md. Контракт каждого правила одинаков в модели, вводе, solver, restore и проверке победы. Прогресс точек выводится из текущего маршрута; отдельного изменяемого счётчика нет, поэтому откат/сброс/restore не расходятся.
Финиш запрещает ранний вход. Стенка запрещает переход в обе стороны, но не удаляет клетки. Точки нумеруются от старта (1); будущий номер недоступен, обычные клетки свободны. Последний номер не обязан завершать поле, если он отдельно не отмечен финишем.
Версия save остаётся v3, существующие 15 уровней не меняются. Свидетельство не ограничивает допустимые решения. Независимый контент-аудит проверяет правила и доказывает их влияние перебором; сравнение solver с независимым оракулом покрывает тупиковые префиксы. Подарок за 20 теперь достижим естественно; его сумма и правила не изменены.

## 2026-10-31: полный банк и независимая навигация наборов
Завершён банк 3×30. `intro` сохраняет все 30 прежних записей, `turns`/`shapes` добавляют 60 уникальных силуэтов. `tools/author-bank.py` детерминированно отбирает из собственных маршрутов, seed 20261031; docs/BANK_CONTENT_AUDIT.json хранит структурные метрики и контрпримеры влияния каждого правила. Повторный запуск выдаёт те же файлы.
Генерация использует ограниченную выборку решений (до 100), поэтому счётчики выборки не выдаются за полное число решений. Независимый validator проверяет witness и отдельный контрпример для каждой семьи ограничений; смешанное правило должно иметь собственное влияние при сохранении остальных. Уникальность маски не равна интересности, визуальный просмотр/плейтест остаются необходимы.
Наборы открываются после трёх первых tutorial; viewSetId — навигационное состояние, не новая ценная запись в save. Resume определяется current levelId, переключение не меняет активную задачу до выбора. После задачи 30 нет автоматического перехода в чужой набор: итоговая сетка предлагает выбрать набор. После 90 — явный финал. Глобальные gifts/offer cadence не обнуляются на границах; за все первые 90 получается 1800+400=2200 монет до покупок и колеса.

## 2026-10-31: обозначения старта и финиша
По замечанию пользователя заменены декоративная стрелка старта и мелкий клетчатый флажок. Старт — маленький светлый гранёный жетон, финиш — углублённое золотистое гнездо той же ромбовидной формы. При завершении в гнезде появляется такой же жетон. Круглая голова маршрута и номерные точки сохраняют отдельный силуэт. Совмещённый финиш с номером не закрывает цифру: ободок остаётся снаружи.
Одна геометрия используется в Phaser, SVG-миниатюрах и эмблеме меню. Подпись говорит «Пустой ромб — последняя клетка». Правила, hit-test, сохранения, банк и экономика не меняются. Это сознательная смена обозначений по пользовательскому фидбеку; прежний пункт про наблюдённую стрелку больше не определяет текущую графику. Сгенерированные растровые ассеты и новые зависимости не нужны.

## 2026-10-31: исправления после UX-аудита
По разрешению пользователя реализованы оба прохода UX-плана (раздел 24 плана). Повтор текущего оплаченного hint не расходует ресурс, ответ переиспользуется только для точного id/version/prefix; кэш transient и не меняет save v3. Правила движения сохранены; moveBlock объясняет три механических запрета. UI не перестраивается целиком на каждом шаге, Phaser объединяет dirty updates в кадр, стили цифр меняются только при изменении.
Недоступная реклама исключена из Continue: offer dismiss выполняется над прежним ledger, x5 скрыт. Подтверждение gift продолжает пользовательский Continue, системный Back — только закрывает.
